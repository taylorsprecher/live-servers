# Personal VPN — WireGuard for Taylor's phones

A WireGuard server (linuxserver/wireguard image) running as the
`vpn` service in the root compose project. Built 2026-11-15 at
Taylor's direction: phones that have no cellular service of their own
get a full-tunnel VPN through this server whenever they are on any
Wi-Fi (or on Taylor's iPhone hotspot) — all of the phone's traffic
exits the internet through this host (52.41.84.116), and the phones
join Taylor's private 10.8.0.0/24 VPN subnet.

## How it is wired (and how it differs from the other services)

- **Not behind the gateway.** Every other service is reached through
  the nginx gateway on :443 because they speak HTTP/WebSocket.
  WireGuard is UDP and cannot pass through nginx, so this container
  publishes **UDP 51820 on the host directly**.
- **The AWS security group must allow inbound UDP 51820.** If it does
  not, the container runs fine but no phone can complete a handshake;
  the fix is one inbound rule (UDP, port 51820, source 0.0.0.0/0) on
  the instance's security group.
- **Keys never leave the host in plaintext.** Server and peer keys
  are generated by the image on first start and live only in the
  `vpn-data` volume (`/config`). `LOG_CONFS=false` keeps the
  generated peer configs — which contain private keys — out of the
  container log. Nothing about the keys is in git.
- **Peers:** `taylor, phone2, phone3, phone4, phone5` (10.8.0.2–.6),
  full tunnel (`ALLOWEDIPS=0.0.0.0/0`), DNS via the server
  (`PEERDNS=auto`).

## Getting a peer config onto a phone (encrypted export)

Peer configs contain private keys, so they never travel through this
public repo's logs or files in plaintext. The export path:

1. Run the **Export VPN peer config** workflow with a peer name.
   On the host, `ops/export-vpn-peer.sh` reads that peer's `.conf`
   from the running container, encrypts it (AES-256-CBC with a random
   file key, the key wrapped with the RSA public key in
   `ops/vpn-export-pubkey.pem`), and prints only base64 ciphertext
   between markers in the run log.
2. The matching private key exists only in Jasmine's workspace
   (`~/workspace/vpn-keys/`, never in git). Jasmine decrypts the
   export, saves the `.conf` and a QR-code PNG into Taylor's private
   files (`~/workspace/your_files/`, mode 600), and Taylor imports it
   into the WireGuard app by scanning the QR code or opening the file.

To revoke a phone: remove its `[Peer]` block from
`/config/wg_confs/wg0.conf` in the volume (or delete the peer and
restart the service), then restart `vpn`.

## Deploy / verify

- Deploy: the **Deploy VPN service** workflow (rsync + 
  `ops/deploy-vpn.sh`) builds/starts only this service and checks
  `wg show`, the host UDP listener, and the usual gateway regression
  checks. It does not use deploy.sh's RAM gate (one-service change,
  same reasoning as ops/deploy-proxy.sh).
- A phone (or any WireGuard client) completing a handshake is the
  end-to-end proof: `wg show` on the server then shows a
  `latest handshake` time for that peer.
