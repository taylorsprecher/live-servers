# FMP-1.0 — Forensic Motion Protocol (increments 1–2)

Telemetry-driven forensic motion visualization, built from the FMP-1.0
front-end engineering guide in Drive ("Front End.docx"): UIStateEngine,
MotionEngine, the Omni Event Bus, and replay timelines — with packet
rematerialization, zone transitions, storm/breach effects, escalation and
collapse cascades rendered over a five-tier network (RAN → DMZ → APP →
DATA → SEC).

## Run it

One process serves both halves (no dependencies, Node 18+):

```sh
cd backend
node server.js          # http://localhost:8787
```

Then open http://localhost:8787 — press **Play**, scrub the timeline, or
click an event marker. Switch **Source** to "Live stream (SSE)" or "Live
stream (WebSocket)" to watch the selected session stream in as live
OmniEvents, use the **Session** picker to load a different replay, and
tune cue durations in the **Motion Script editor** (applies live; "Save
as new version" persists a new versioned script object).

A fully self-contained static demo (no backend) lives in `demo/` —
regenerate it with `node build-demo.js`. Tests: `node tests/smoke.test.js`.

## Layout

```
backend/
  server.js       HTTP API + SSE + WebSocket streams + static frontend host
  s3store.js      S3-shaped storage interface over a local directory
  normalize.js    raw telemetry -> OmniEvent normalization (guide mapping)
  data/forensics-bucket/
    replay/session-2026-10-08.json       sample replay session (32 events)
    replay/session-2026-11-02.json       sample session 2 (25 events:
                                         ICMP recon sweep + incident echoes)
    motion-scripts/fmp-motion-v1.json    versioned motion script (cue durations)
demo/
  index.html      self-contained static demo (generated by build-demo.js)
tests/
  smoke.test.js   engine + backend smoke tests (31 assertions)
frontend/
  index.html
  css/styles.css  cinematic CSS motion language (guide §3)
  js/uiStateEngine.js   state store: theme/sidebar/mode/playhead/severity/log
  js/motionEngine.js    cue registry + sequencer; script-driven durations
  js/omniBus.js         normalization mirror, chronological ordering,
                        graceful-degradation buffering
  js/viewport.js        SVG scene: zones, routes, capsules, rings, particles
  js/timelineMotion.js  play/pause/scrub/jump/speed replay engine
  js/app.js             boot order + event->cue wiring (guide mapping table)
```

## API

| Endpoint | What |
|---|---|
| `GET /api/health` | status + stub notice |
| `GET /api/buckets` | S3 ListBuckets (stub) |
| `GET /api/buckets/:bucket/objects?prefix=` | S3 ListObjects (stub) |
| `GET /api/replay?bucket=&key=` | normalized, chronologically ordered OmniEvent timeline |
| `GET /api/motion-script?bucket=&key=` | versioned motion script JSON |
| `POST /api/motion-script?bucket=&key=` | save a new script version (keys constrained to `motion-scripts/*.json`) |
| `GET /api/events/stream?speed=1&key=` | SSE live OmniEvent stream (loops the selected session) |
| `WS /api/events/ws?speed=1&key=` | WebSocket live OmniEvent feed (minimal RFC 6455, zero-dependency) |

## What is stubbed

- **AWS S3** — replay timelines and motion scripts are local files under
  `backend/data/<bucket>/<key>`, accessed only through `s3store.js`,
  which mirrors the S3 API shape (ListBuckets / ListObjects / GetObject).
  Swapping in real S3 later touches only that module.
- **Telemetry sources** — CloudWatch / Kinesis / VPC Flow / Lambda feeds
  are represented by the sample session's raw records; `normalize.js`
  applies the guide's mapping table to them. No AWS account, credentials,
  or network calls are involved.
- **Live mode** — the SSE and WebSocket streams replay the selected
  sample session on a loop rather than a real Kinesis/CloudWatch feed.
  Stopping the server while in Live mode exercises the frontend's
  graceful-degradation path (events buffer, banner shows, UI state
  stays intact).

## Motion grammar implemented

`packet:rematerialize` (materialize ring + sparks → route re-illumination
→ camera micro-sweep → capsule travel), `packet:incidentEcho` (ghost
capsules bounce back along the packet's route), `zone:deactivate`/`zone:activate`
+ `zone:focus`, `incident:tamper`, `incident:dlq`, `incident:icmp`
(ICMP probe rings), `storm:burst`
(particle density field + shockwave rings + severity-modulated camera
turbulence), `breach:surge`, `escalation:cascade` (forward tier cascade),
`collapse:cooling` (CollapseEngine reverse cooling cascade + arc
dissolution), and the timeline cues `timeline:play` / `timeline:scrub` /
`timeline:reverse`.
