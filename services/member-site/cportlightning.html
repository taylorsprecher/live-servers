Cport-Lightening

The Python build set for all three readings of Cport-Lightening — serial-port firmware, PyTorch Lightning, and Core Lightning node upgrades — installed and verified Nov 26, 2026.

What’s in the set

  • cport_lightning_serial_upgrade.py — firmware over a serial/COM port (pyserial): size + chunk count + SHA-256 in the handshake, an ACK per chunk, COMMIT to finish.
  • cport_lightning_pytorch_upgrade.py — the PyTorch Lightning pattern for porting a model onto the Trainer, as a clean LightningModule.
  • cport_lightning_cln_upgrade.py — the small Core Lightning snapshot helper (pre/post around a restart).
  • cln_upgrade_workflow.py — the complete CLN upgrade workflow: capture, clean stop, cold backup, upgrade, verify.
  • cln_docker_upgrade.py — the Dockerized variant with custom plugins and strict pre-flight checks.

Before any CLN upgrade — the safety rules

  • Never restore a stale channel database. An older lightningd.sqlite3 put back online after channel activity can force-close channels and lose funds. After an upgraded node has started and connected to peers, do not roll the database back at all.
  • Preserve hsm_secret and emergency.recover offline, plus any HSM passphrase.
  • Upgrades are often one-way — archive the pre-upgrade snapshot and old binaries.
  • Regtest dry run first, on the node’s own host.

Honest status: there is no lightningd node in the fleet yet, so the workflows’ main upgrade paths have not been run — everything testable without a node was tested, and the rest waits for a node to exist.
